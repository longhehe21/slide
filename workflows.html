🎬 5 Workflow điển hình

1. Task mới — bình thường

$ cd ~/my-project $ claude > Thêm chức năng login với validate email + mật khẩu > 8 ký tự. Viết test luôn. # Claude tự đọc project → code → test → báo done

2. Hôm sau muốn tiếp tục task dở

$ cd ~/my-project $ claude --continue # Quay lại context lần trước, không phải kể lại từ đầu

3. Quay lại task tuần trước

$ claude --resume # Mở picker → chọn session cũ → tiếp tục

4. Change LỚN — plan trước

$ claude --permission-mode plan > Refactor authentication thành module riêng. # Claude lên kế hoạch → review → execute

5. Context rối → reset

# Trong session, gõ: > /clear # Xóa context → bắt đầu prompt mới với đầu sạch

✍️ 3 nguyên tắc viết prompt

1. Cụ thể, không mơ hồ

prompt-comparison.md
❌ "thêm test"
❌ "fix bug"
❌ "làm code đẹp hơn"

✅ "Viết unit test cho hàm loginUser() trong src/auth/user.ts."
   "  Test cases: email + password đúng → true,"
   "  password rỗng → false, email sai format → false."
   "  Chạy test sau khi viết xong."

2. Chỉ rõ file / vị trí

❌ "thêm chức năng login" ✅ "Thêm chức năng login. Tạo file src/pages/login.tsx. Dùng API endpoint POST /api/auth/login. Validate trong src/utils/validate.ts."

3. Yêu cầu verify (test/chạy/screenshot)

❌ "viết hàm xong rồi" ✅ "Viết hàm xong, chạy npm test để verify pass. Nếu fail, fix cho đến khi pass."
💡 Công thức prompt tốt
WHAT (làm gì cụ thể) + WHERE (file nào) + HOW TO VERIFY (test/chạy gì). Đủ 3 cái → ít phải sửa lại.

🚦 Khi nào dùng plan mode?

Tình huống Plan mode?
