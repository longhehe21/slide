Merge vs Rebase — cùng kết quả, khác lịch sử

🔀 MERGE phổ biến

# Đứng ở feature branch git merge main # Lịch sử có commit merge thừa: * Merge branch 'main' into feat/login |\ | * feat: thêm login * | main: cập nhật README |/ * init
Giữ toàn bộ history thật, nhưng thêm commit merge thừa → đồ thị git rối, log chằng chịt.

🔄 REBASE sạch

# Đứng ở feature branch git rebase main # Lịch sử thẳng băng: * feat: thêm login * main: cập nhật README * init
Commit của feature được "xếp lại" trên đầu main → lịch sử tuyến tính, không commit merge thừa.
⚠️
Golden rule: KHÔNG rebase nhánh đã git push lên public (main, develop, hoặc branch đã share team).
→ Lý do: rebase viết lại hash commit. Người khác đã pull về sẽ vỡ trận.
OK rebase: branch riêng của mình chưa share.
