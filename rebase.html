git rebase main vs git merge main #02

⊙ Open @longhehe21 opened this issue 2 hours ago
@longhehe21 commented · 2 hours ago

Cả hai đều cập nhật nhánh của bạn với main mới nhất, nhưng tạo lịch sử khác nhau.

🔀 Cách 1: git merge main

# Khi đang ở nhánh của mình $ git merge main # Lịch sử có thêm 1 commit "gộp" thừa: * Gộp main vào nhánh |\ | * Thêm trang đăng nhập * | Cập nhật README ở main |/ * commit đầu tiên
📝 Đặc điểm
Giữ đủ lịch sử thật, nhưng có 1 commit "gộp" thừa. Khi log ra nhiều nhánh sẽ rối.

🔄 Cách 2: git rebase main

# Khi đang ở nhánh của mình $ git rebase main # Lịch sử thẳng băng, không commit thừa: * Thêm trang đăng nhập * Cập nhật README ở main * commit đầu tiên
💡 Đặc điểm
Commit của bạn được "xếp lại" lên trên main → lịch sử tuyến tính, sạch.
⛔ QUY TẮC VÀNG
KHÔNG rebase code đã đẩy lên nhánh chung (main, develop, hoặc nhánh team đã pull về).
Lý do: rebase tạo lại commit mới khác commit cũ. Người khác pull về sẽ thấy 2 lịch sử khác nhau → loạn.
Chỉ rebase nhánh riêng của mình, chưa share ai.
